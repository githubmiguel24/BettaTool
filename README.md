# bettafish

**Uncertainty-Aware Neuro-Symbolic Morphometrics for Rule-Based Halfmoon Longfin Betta Fish Assessment**
(Group 4, PUP-CCIS thesis). A photo goes in; the system locates 13 landmarks, turns them into five IBC form measurements
with calibrated uncertainty, and either issues a Pass/Fault verdict or **defers to a human judge** when the uncertainty
could change the verdict.

## Run it

```bash
# Terminal 1 - backend (needs data/ and the checkpoints under backend/training/runs/, which are not in git)
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload        # http://localhost:8000

# Terminal 2 - frontend
cd frontend
npm install
npm run dev                          # http://localhost:5173 (/analyze, /reports, /export, /health are proxied to :8000)
npm run build
```

Python 3.10+. Set `VITE_API_BASE` in `frontend/.env.local` to use a backend on another host; login uses Supabase
(`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`).

## How the system works

Three tiers, wired end to end in `backend/app/pipeline.py`:

1. **Perceptual tier**: HRNet-W32 (ImageNet-pretrained) with a heatmap head and a covariance head. For each of
   13 landmarks it gives a mean (soft-argmax of the heatmap) and a 2x2 covariance.
2. **Analytical tier**: five IBC measurements (`morphometrics.py`: caudal spread angle; dorsal, anal and caudal fin / body
   ratios; anal fin length-to-width ratio), Jacobian + ISO GUM propagation (`u_c = sqrt(J Sigma J^T)`, `U = 2 u_c`), and
   **per-criterion measurement factors** (`measurement_factor.py`, read from the `measurement_factor:` block of `training/configs/hrnet_w32.yaml`) that make the
   reported 95% bands actually cover about 95% of cases.
3. **Decisional tier**: IBC thresholds and rule engine, plus the TSI gate (`tsi.py`): `TSI = |measurement - threshold| / (2 ||J||)`
   (px) and `sigma_hat = sqrt(J Sigma J^T) / ||J||`, the isotropic keypoint error equivalent to the predicted covariances, times its
   own measurement factor (`tsi_scale`, fitted on VAL). A criterion is decided only if `sigma_hat < TSI`, otherwise it is "Defer to Judge".

## Settings and endpoints

Settings are in `backend/app/core/config.py` (override with environment variables or `.env`):

| Setting | Default | Meaning |
|---|---|---|
| `MODEL_CHECKPOINT_PATH` | `training/runs/v3_run/checkpoints/best_nll.pt` | keypoint model |
| `BETTA_CONFIG_PATH` | `training/configs/hrnet_w32.yaml` | its `measurement_factor:` block holds per-criterion `scale` (reported U) and `tsi_scale` (gate); 1.0 for a criterion not listed |
| `MFLD_CHECKPOINT_PATH` | `training/runs/mfld_best.pt` | only for the comparison tab; the tab reports a clear error if the file is missing |
| `DEVICE` | `cpu` | `cuda` on a GPU machine |

Endpoints:

- `POST /analyze`: one photo -> keypoints with uncertainty, five measurements with Pass / Fault / Defer, saved to history.
- `POST /analyze/compare`: the same photo through our model and MFLD-Net with per-keypoint disagreement. Nothing is saved.
- `GET /analyze/compare/benchmark`: measured test-set comparison (ours vs MFLD-Net) and example photos with human labels.
- `GET /reports`, `GET /reports/{id}`, `GET /reports/{id}/export`, `GET /health`.

## Training and evaluation

Files in `backend/training/`:

| File | Purpose |
|---|---|
| `prepare_annotations.py` | normalise a Roboflow COCO-keypoints export into `data/annotations/annotations.json` |
| `splitting.py` | grouped + stratified 70/15/15 split -> `data/splits/{train,val,test}.json` |
| `dataset.py`, `transforms.py`, `targets.py` | fish-box crop + letterbox to 384 px, augmentation, heatmap targets (round or elongated) |
| `losses/` | heatmap MSE or KL, Gaussian NLL (beta-NLL) |
| `train_hrnet.py` | the training loop (two stages, EMA, noisy-label options, `best` / `best_nll` / `best_tip` checkpoints) |
| `evaluate.py` | evaluation on a split: localisation, calibration, overlays, `predictions.npz` |
| `export_mfld_benchmark.py`, `mfld_full_comparison.py` | the ours-vs-MFLD-Net numbers shown in the app's comparison tab |
| `metrics/`, `utils/`, `viz/`, `configs/` | metrics, config loading and run logging, overlay rendering, YAML configs |

Configs: `configs/base.yaml` holds the defaults and `configs/hrnet_w32.yaml` (the deployed model) is merged on top of it. The
model uses noisy-label training (ambiguous labels at half weight, EMA-teacher blending, trimmed loss on fin tips), elongated
fin-tip targets with a KL heatmap loss, EMA weights, NLL that trains sigma only, early stopping and checkpoint choice by
validation NLL, and a single forward pass at inference. Its `measurement_factor:` block holds the per-criterion uncertainty scales.

SAM-based fin silhouettes were tested and dropped (every variant made fin-tip error worse); those scripts were deleted.

## Known gaps

- **Input framing:** the model was trained and evaluated on crops of the labelled fish box, but the app feeds the whole photo
  (`perception/preprocess.py`). That costs accuracy (mean error about 15.8 -> 18.6 px on test, deferral about 27% -> 35%). A
  fish detector before the model is the open fix.
- **Occlusion:** there is no dedicated occlusion signal (the visibility head, removed after v3, stayed near 1.0 even when a
  keypoint was covered because it saw almost no occluded labels), so occlusion is caught only indirectly through wider uncertainty and more deferrals. Occlusion-aware training is an open idea.
- **Calibration** must be refitted whenever the model or the inference mode changes (workflow step 3).
- The IBC numeric thresholds for the fin-body ratios and the anal length-to-width ratio in `decisional/ibc_standards.py` need
  confirming against the IBC Exhibition Standards Book; only the caudal spread bands come directly from it.
- The backend keeps reports in an in-memory dict (`core/db.py`, lost on restart); the frontend stores its history in Supabase.
- The live comparison overlay runs the older MFLD-Net checkpoint (28% of the data, whole-image input); the benchmark table uses
  the retrained one. A single uploaded photo has no ground truth, so the overlay shows disagreement, not who is right.
