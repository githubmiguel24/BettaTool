# bettafish

**Uncertainty-Aware Neuro-Symbolic Morphometrics for Rule-Based Halfmoon Longfin Betta Fish Assessment**
(Group 4, PUP-CCIS thesis). A photo goes in; the system locates 13 landmarks, turns them into five IBC form measurements
with calibrated uncertainty, and either issues a Pass/Fault verdict or **defers to a human judge** when the uncertainty
could change the verdict.

## Run it

```bash
# Terminal 1 - backend (needs data/ and the checkpoints under backend/training/runs/, which are not in git)
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload        # http://localhost:8000

# Terminal 2 - frontend
cd frontend
npm install
npm run dev                          # http://localhost:5173 (/analyze, /reports, /export, /health are proxied to :8000)
npm run build
```

Python 3.10+. Set `VITE_API_BASE` in `frontend/.env.local` to use a backend on another host; login uses Supabase
(`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`).

## How the system works

Three tiers, wired end to end in `backend/app/pipeline.py`:

1. **Perceptual tier**: HRNet-W32 (ImageNet-pretrained) with a heatmap head, a covariance head and a visibility head. For each of
   13 landmarks it gives a mean (soft-argmax of the heatmap) and a 2x2 covariance.
2. **Analytical tier**: five IBC measurements (`morphometrics.py`: caudal spread angle; dorsal, anal and caudal fin / body
   ratios; anal fin length-to-width ratio), Jacobian + ISO GUM propagation (`u_c = sqrt(J Sigma J^T)`, `U = 2 u_c`), and
   **per-criterion calibration scales** (`calibration.py`, read from `training/runs/v3_run/calibration.json`) that make the
   95% bands actually cover about 95% of cases.
3. **Decisional tier**: IBC thresholds and rule engine, plus the abstention gate: a criterion is decided only if
   `|measurement - threshold| > U`, otherwise it is "Defer to Judge".

## Settings and endpoints

Settings are in `backend/app/core/config.py` (override with environment variables or `.env`):

| Setting | Default | Meaning |
|---|---|---|
| `MODEL_CHECKPOINT_PATH` | `training/runs/v3_run/checkpoints/best_nll.pt` | keypoint model |
| `BETTA_CALIBRATION_PATH` | `training/runs/v3_run/calibration.json` | per-criterion uncertainty scales (scale 1.0 for a criterion not in the file) |
| `USE_FLIP_TTA` | `false` | flip test-time augmentation: doubles inference time for about 1-2% lower error with v3; calibration is fitted in the same mode |
| `MFLD_CHECKPOINT_PATH` | `training/runs/mfld_best.pt` | only for the comparison tab; the tab reports a clear error if the file is missing |
| `DEVICE` | `cpu` | `cuda` on a GPU machine |

Endpoints:

- `POST /analyze`: one photo -> keypoints with uncertainty, five measurements with Pass / Fault / Defer, saved to history.
- `POST /analyze/compare`: the same photo through our model and MFLD-Net with per-keypoint disagreement. Nothing is saved.
- `GET /analyze/compare/benchmark`: measured test-set comparison (ours vs MFLD-Net) and example photos with human labels.
- `GET /reports`, `GET /reports/{id}`, `GET /reports/{id}/export`, `GET /health`.

## Training and evaluation

Files in `backend/training/`:

| File | Purpose |
|---|---|
| `prepare_annotations.py` | normalise a Roboflow COCO-keypoints export into `data/annotations/annotations.json` |
| `splitting.py` | grouped + stratified 70/15/15 split -> `data/splits/{train,val,test}.json` |
| `dataset.py`, `transforms.py`, `targets.py` | fish-box crop + letterbox to 384 px, augmentation, heatmap targets (round or elongated) |
| `losses/` | heatmap MSE or KL, Gaussian NLL (beta-NLL), visibility BCE |
| `train_hrnet.py` | the training loop (two stages, EMA, noisy-label options, `best` / `best_nll` / `best_tip` checkpoints) |
| `evaluate.py` | evaluation on a split: localisation, calibration, overlays, `predictions.npz` |
| `recalibrate.py` | fits the per-criterion uncertainty scales (`calibration.json`) on VAL |
| `gate_analysis.py` | learned-vs-constant-margin gate, base rates, forced-vs-gated decisions (VAL and TEST) |
| `export_mfld_benchmark.py`, `mfld_full_comparison.py` | the ours-vs-MFLD-Net numbers shown in the app's comparison tab |
| `benchmark.py` | throughput / memory probe on synthetic batches |
| `metrics/`, `utils/`, `viz/`, `configs/` | metrics, config loading and run logging, overlay rendering, YAML configs |

Configs: `configs/base.yaml` holds all defaults and an experiment config is merged on top of it.
`hrnet_w32.yaml` is the original run; `hrnet_w32_v2.yaml` adds stronger augmentation, weight decay 5e-2 and per-epoch val NLL /
coverage; **`hrnet_w32_v3.yaml` is the deployed model**: v2 plus noisy-label training (ambiguous labels at half weight,
EMA-teacher blending, trimmed loss on fin tips), elongated fin-tip targets with a KL heatmap loss, EMA weights, NLL trains
sigma only, early stopping and checkpoint choice by validation NLL, and `tta.enabled_eval: false` (single pass, matching the app).

Typical workflow (from `backend/`):

```bash
# 1. train (Kaggle or a GPU machine); a run folder appears under training/runs/<timestamp>_<experiment>/
python -m training.train_hrnet --config training/configs/hrnet_w32_v3.yaml

# 2. evaluate the chosen checkpoint on VAL and save its predictions
python -m training.evaluate --config training/configs/hrnet_w32_v3.yaml \
    --checkpoint training/runs/v3_run/checkpoints/best_nll.pt --split val

# 3. refit the uncertainty scales on those VAL predictions (needed after ANY change of model or inference mode)
python -m training.recalibrate training/runs/v3_run/eval_val/predictions.npz --out training/runs/v3_run/calibration.json

# 4. report test numbers once checkpoint and scales are frozen
python -m training.evaluate --config training/configs/hrnet_w32_v3.yaml \
    --checkpoint training/runs/v3_run/checkpoints/best_nll.pt --split test
python -m training.gate_analysis --val training/runs/v3_run/eval_val/predictions.npz \
    --test training/runs/v3_run/eval_test/predictions.npz --calibration training/runs/v3_run/calibration.json

# 5. rebuild the comparison-tab benchmark after a model change (needs mfld-net/predictions_test.npz)
python -m training.export_mfld_benchmark
```

Why the checkpoint rule matters: with "best mean error" the chosen checkpoint is stage-2 epoch 0, before the covariance loss is
switched on, so its uncertainty is untrained. v3 selects by validation NLL.

Run folders (`training/runs/`, gitignored): the active run is `v3_run/` (`checkpoints/best_nll.pt`, `calibration.json`,
`eval_val/`, `eval_test/`); the MFLD-Net comparison checkpoint is `mfld_best.pt`; earlier runs are in `archive/` (below).

Things to know: all evaluation uses the labelled `fish_box` (+15% padding) as the crop; the deployed app feeds the whole photo
instead. Calibration scales are fitted on VAL, so VAL coverage is in-sample and TEST is the honest check. Fin-tip labels are
ambiguous (two labellings of the same photo disagree by about 15 px median), which bounds fin-tip accuracy.

## Results (v3, test split, 247 images)

- **Keypoints:** mean error 16.1 px (median 6.4); body landmarks 2-7 px, fin tips about 31 px.
- **Decisions:** after calibration the uncertainty bands cover the true measurement 92-97% of the time; on the cases the system
  decides it is about 99.7% right, and it defers about 28% of criterion assessments (forced decisions on every image: about 96%).
- **Against a retrained MFLD-Net** (same split and fish-box crops, scored on identical images): about 2.4x lower keypoint
  error, about 2x lower measurement error, ours has the lower mean error on 96% of test images. MFLD-Net is 41x smaller
  (0.72 M vs 29.5 M parameters) and about 10x faster. The comparison tab in the app shows these numbers, generated from real
  predictions, plus labelled example photos.
- **Robustness (val):** box shifts up to 20% and size changes of +-15% change the mean error by under 1 px; a box that cuts
  the fish (70%) raises it from 14.1 to 17.7 px with deferral rising from 26% to 44%. Under synthetic occlusion the visibility
  head does not react, but deferral rises sharply and decided-case accuracy stays at 99% or better.

## Frontend

`frontend/src/views/pages/UploadView.jsx` is the New Analysis page: it sends the photo to `POST /analyze`, draws the keypoints
and uncertainty, lists the five measurements with Pass / Fault / Defer, saves to history and exports PDF / CSV. Its second tab,
**Compare with MFLD-Net** (`src/components/CompareTab.jsx`), shows both models on the uploaded photo, labelled test photos with
the human labels, and the measured benchmark table; every number comes from the backend. Other pages: History, Report, login.

## Analysis scripts

`analysis/` holds the experiments behind the thesis numbers. They are not needed to train or serve the model. Run them from
`backend/` so the relative `training/runs/...` and `data/...` paths resolve:

```bash
cd backend
PYTHONPATH=.. python -m analysis.robustness_tests --boxes --occlusion
```

Most scripts target a specific run; check the paths at the top before reusing one with a different run.

| Script | Question it answers |
|---|---|
| `robustness_tests.py` | How do shifted/shrunk/enlarged fish boxes and synthetic occlusion change error, coverage and deferral? |
| `occlusion_aware_uncertainty.py` | Can TTA disagreement or heatmap spread make the uncertainty notice occlusion? (No useful gain.) |
| `postproc_experiments.py` | Local/DARK decoding, TTA-disagreement covariance, per-group scaling, caudal-centre geometry (only the covariance idea helped, slightly). |
| `v3_improvement_experiments.py`, `tta_ensemble_experiment.py` | Weight soup, two-model ensemble, multi-scale TTA (ensemble about 3% better, not adopted; multi-scale hurts). |
| `tta_signal_analysis.py`, `signal_significance.py` | Is TTA disagreement a better uncertainty signal than the learned sigma, with bootstrap intervals and McNemar tests. |
| `tta_wrap_check.py`, `flip_check.py` | The `torch.roll` wrap-around bug in flip TTA and the right-facing-snout failure it caused. |
| `measurement_coverage.py`, `fixed_accuracy_gate.py` | Raw per-criterion coverage; deferral needed for a target decided-case accuracy. |
| `label_review_sheet.py` | Review sheets of the val images with the largest fin-tip errors, with original file names. |

SAM-based fin silhouettes were tested and dropped (every variant made fin-tip error worse); those scripts were deleted.

## Archived runs

`backend/training/runs/archive/` holds superseded models for reference; nothing there is read by the app.

| Folder | What it is |
|---|---|
| `v0_local_trial_runs_2026-09/` | Seven early local runs (15 and 22 Sep 2026), mostly config-only stubs; one holds a stage-1 `last.pt` from an interrupted run. |
| `v1_hrnet_w32_first_kaggle_run_best-at-stage2-epoch0/` | The first full Kaggle run. `best.pt` is stage-2 epoch 0, before the NLL loss started, so its uncertainty is untrained. Also holds the `*_buggy_tta` results from before the flip-TTA wrap-around bug was fixed. |
| `v2_hrnet_w32_stronger_aug_last-epoch40/` | The v2 run (`checkpoints/last.pt` is stage-2 epoch 40). Position error about the same as v3; uncertainty clearly worse (95% keypoint coverage 0.78 vs 0.84). |

Duplicate files were removed only when byte-identical (SHA-256). Files that share a name across runs (for example
`eval_*/overlay/*.png`, `last.pt`) have different content and were kept.

## Known gaps

- **Input framing:** the model was trained and evaluated on crops of the labelled fish box, but the app feeds the whole photo
  (`perception/preprocess.py`). That costs accuracy (mean error about 15.8 -> 18.6 px on test, deferral about 27% -> 35%). A
  fish detector before the model is the open fix.
- **Occlusion:** the visibility head stays near 1.0 even when a keypoint is covered (it saw almost no occluded labels), so
  occlusion is caught only indirectly through wider uncertainty and more deferrals. Occlusion-aware training is an open idea.
- **Calibration** must be refitted whenever the model or the inference mode changes (workflow step 3).
- The IBC numeric thresholds for the fin-body ratios and the anal length-to-width ratio in `decisional/ibc_standards.py` need
  confirming against the IBC Exhibition Standards Book; only the caudal spread bands come directly from it.
- The backend keeps reports in an in-memory dict (`core/db.py`, lost on restart); the frontend stores its history in Supabase.
- The live comparison overlay runs the older MFLD-Net checkpoint (28% of the data, whole-image input); the benchmark table uses
  the retrained one. A single uploaded photo has no ground truth, so the overlay shows disagreement, not who is right.
